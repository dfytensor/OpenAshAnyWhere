## 一、§6.1 φ 完备性（WAGGLE 盲区搜索）

### 1.1 文档自己的失败判据被触发

按 §6.1 协议：固定控制器，枚举候选输出，找"所有 |z_i|≤1 但真实质量差"的样本。

| φ 配置 | 盲区率 (界内∩可救蜜源, net≤0) | 判定 (>5% ⇒ 不完备) |
|---|---|---|
| **原始 φ = {z1,z2,z3}** | **11.06%** (510/4612) | ❌ **不完备** |
| + z4 = 1[found] 谓词 | 4.91% | ✅ 修复达标 |
| + z5 = 飞行成本 (单独) | 11.14% | 无效 |
| z4 + z5 全加 | 4.95% | 达标但 z5 冗余 |

### 1.2 两个方法论修正（验证中发现，文档未写）

1. **不可救蜜源污染**：8 个蜜源中 3 个基线净能量为负（−0.70/−2.81/−4.65）——
   无论输出多完美都饿死。不排除它们，盲区率会被高估（C 臂闭环样本中 34.6%
   "界内但饿死" ≈ 3/8 = 37.5% 的不可救占比）。**盲区统计必须条件化在可救场景上。**
2. **悬崖带定位**：z2 归一化半径 600 m vs found 判据 550 m——界内允许的误差带
   [550,600) 是 found 必死区。盲区机制分解：**found 悬崖 58.4%**，
   near-cliff 薄利样本 ~40%（found 但报远 → 飞行成本吃掉低蜜质收益）。

### 1.3 残余 4.91% 的本质：环境不可救性，不是 φ 的错

修复后残余样本全部是"薄利蜜源"（base +3.6~+6.0, qt 0.73~0.85, err 450~535）：
found 成立、R 合理、蜜质拉满，net 仍 −0.5~−2.2。**任何输出侧变量都救不了
"场景本身盈亏平衡点太薄"**——这精确对应文档 §6.1 的 allostasis 预言：
**边界 h 必须按上下文条件化**（S1 base=+10.3 的 h 与 S0 base=+3.6 的 h 不该相同），
全局常数 h 无法同时服务肥场景与薄场景。

### 1.4 冗余覆盖检查（§6.1 方案 2）

| 候选变量 | 界内样本分布 | 判定 |
|---|---|---|
| 逐舞蹈 w 计数方差 | 0.37~24.0（环境不消费方差） | 冗余 |
| 角度误差 | 0.2°~179.7°（colony2 的 found 只用距离） | 冗余 |
| 飞行成本 cost | 好样本 p99=23.2 | 冗余（信息被 z2/z3+found 覆盖） |

### 1.5 副产品

只逛可救蜜源（跳过 3 个陷阱源）的 C 臂 300 轮末能量中位 **+2117**（对照原实验
全 8 源的 568）。"余量监测 → 弃权 hopeless 场景"策略自然涌现。

**§6.1 判读：文档把 φ 完备性列为最高风险是准确的——失败判据真的触发了（11.06%）。
但修复成本低（一个 found 谓词），且残余盲区指出了比加维度更深的修法：上下文条件化边界。**

## 二、§6.2 真实 LLM 耦合矩阵估计（Spark-X2.5-1.7B）

### 2.1 协议按文档执行，但小信号协议先撞上"死区"

文档协议（±δ 有限差分, δ~0.5）实测：**±0.5/±1 logit bias 下所有变量纹丝不动**
（len 恒 90.4，refuse 恒 0）。强 LM 的 logit 把 ±1 偏置完全吸收。

**先做权限曲线标定**（u∈{0,±2,±4,±8,±16}，8 prompts, 96 tok, greedy）：

| 作动器 | 死区 | 工作窗口 | 崩坏点 |
|---|---|---|---|
| u_refuse (拒绝词偏置) | **±8 全死** | **无** | +16 → 退化复读"无法拒绝无法拒绝…" |
| u_hedge (对冲词偏置) | ≤±1 | [2,8]: 0→0.44→1.42/百字 | +16 → 45.8/百字（复读） |
| u_len (句号/EOS 偏置) | ≤±1 | [2,8]: 165→151→82 字 | +16 → 0（立即 EOS） |

### 2.2 工作窗口内的耦合矩阵（11 设置网格，有限差分）

| C (行=变量, 列=控制) | u_len | u_hedge |
|---|---|---|
| **z_len (字)** | **−2.85 (±4) / −5.85 (±8)** | +0.19 |
| **z_hedge (/百字)** | +0.02 | **+0.055 (±4) / +0.089 (±8)** |
| z_refuse | 0 | 0 |

- **跨模块边极弱**：dlen/du_hedge = +0.19 字/单位（基线的 0.1%/单位），
  dhedge/du_len = +0.02。**在 logit-bias 作动器族下，两模块近似解耦**——
  文档 §3.2 手写的 0.5~0.9 强度跷跷板在该作动器族下**未复现**。
  耦合强度是 (模块, 作动器族) 的联合属性，不是 LM 的固有属性。
- **叠加原理**：len 在局部线性极好（u=(4,4) 用 ±4 局部 C 预测 154.5 vs 实测
  154.6，**0.1% 误差**）；hedge 凸性超可加（单轴 0.24+0.44=0.68，组合实测 1.10，
  **+62% 超线性**）；负向被 0 地板钳制（hedge 密度不能为负）。
- **refuse 结论**：logit bias 无法诱导真实拒绝行为（死区直达崩坏），需要
  prompt 级或 activation steering——这是作动器族结论，不是架构否证。

### 2.3 元观察：作动器幅值自身有可行域

u ∈ [~2, ~8] 之外：死区（无效）或崩坏（复读/EOS）。**"可行域"哲学递归地
适用于控制旋钮本身**——增益/幅值不该最大化，该回中。这为文档 §1.3 决策一
（增益存在内部最优）在真实 LM 上提供了一个直接对应物。

## 三、对文档的修订建议（按证据强度排序）

1. **§6.1 失败判据会真实触发**（本验证 11.06%>5%）：φ 完备性不是纸面风险。
   "悬崖类真值判据"（found/命中/编译通过）必须显式进 φ，其归一化半径必须
   与真值判据半径一致（550/600 的不一致是本次盲区的主因）。
2. **盲区统计要条件化在可救场景上**：不可救场景（基线即负收益）会污染盲区率，
   应单独报告为"环境不可救性"，并驱动 h 的上下文条件化（allostasis 的可操作化）。
3. **§6.2 协议需加前置步骤：权限曲线标定**。先扫 {0,±2,±4,±8,±16} 找工作窗口，
   再在窗口内做有限差分——否则小信号估计出 C≈0 的假阴性。
4. **耦合矩阵 O 的量级依赖作动器族**：logit-bias 下跨边 ≪ 手写跷跷板。
   "没人去估计 O"（§5.5）之外还要加一句："换了作动器族，O 会变"。
   activation steering / prompt 控制下的 O 估计是下一个实验。
5. hedge 的超可加性与 0 地板说明：**多旋钮组合的线性预测只在局部成立**，
   L3 内化层用局部 C 的前提是 u 离标定点不远——可行域控制恰好保证这一点，
   两者是自洽的。

## 四、复现

```bash
cd viablelm/waggle
python phi_blindspot.py     # 盲区初扫 + 冗余检查 (~25 min, 含 5 万次采样)
python phi_blindspot2.py    # 干净盲区率 + 机制分解 + 修复A
python phi_blindspot3.py    # 完整修复验证 + C臂可救源末能量

cd ../llm
python o_estimate_spark.py  # 小信号协议 (17 设置, 撞死区, ~74 min)
python authority_curve.py   # 权限曲线 (12 设置, ~36 min)
python authority_grid.py    # 工作窗口网格 (11 设置; 断点续跑用 one_setting.py <i>)
python resume_grid.py       # 汇总 + 叠加原理检验
```

已知工程注意：共享 GPU 上单设置约 3~12 分钟（视 contention），进程可能被
OOM 静默杀死——`one_setting.py` 的单设置单进程 + JSON 增量落盘模式可断点续跑。
