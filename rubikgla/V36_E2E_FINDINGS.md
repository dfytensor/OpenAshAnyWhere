# v36 端到端验证报告 (V36_E2E_FINDINGS)

日期: 2026-10-28 · 环境: RTX 4090D, torch 2.14.0+cu126, triton 3.8.0, python 3.12.8 (.venv-spark25)
产物: `v36_math_verify.py` (数学验证) · `v36_e2e_train.py` (端到端实验+探针) · `v36_probe.py` (微探针)

## 一、已确认的结构性结论 (高置信)

### 1. bank 接力数学基础 ✅
两段扫描(s0 注入)与单次全扫描**逐位一致** (kernel vs kernel diff=0, kernel vs PyTorch 1.2e-05)。
kernel `HAS_S0` 路径可直接用于 v36 的 chunk 独立扫描与续扫。

### 2. 核心保持主张 ✅ (实测与理论比 0.98–1.01)
| L | 单state 保持系数 | 多state 保持系数 | 增益 |
|---|---|---|---|
| 256 | 0.603 | 0.779 | 1× |
| 1024 | 0.127 | 0.758 | 6× |
| 4096 | **2.7e-04** | **0.763** | **2789×** |
| 4096 (eta=0.1) | 3.9e-08 | 0.232 | ~6×10⁶ |

多state 保持恒定为 exp(-rate·128), 与总长无关 → "检索精度不退化"成立。
eta 的数据依赖擦除只惩罚单state, 方向对 v36 更有利。

### 3. 梯度短路效应 ✅ (bank 相对单state的结构优势)
初始化时源写入的 value 行梯度: 多state **1.7e-01** vs 单state **1.5e-03 (108×)**。
梯度无需穿越衰减链即达源写入——bank 读出把长程信用问题从"链上传播"变成"一步直达"。

### 4. 零初始化检索门无信号 ⚠️ (Test C)
softmax(q·W·summary(Sᵢ)) 零初始化 top-1 = 6.9% (随机 6.25%)。
**检索头必须端到端训练, 不可冻结**; 建议 aux marker-retrieval 损失暖启动。

### 5. 架构定律: 非上下文写入无法绑定配对 ⚠️ (新发现, 重要)
单 token 写入 (k,v 均为自身 embedding 的函数) 的线性 state 中,
key 与 value 是**两个独立外积**, 配对信息不在 state 的任何双线性项里。
**联想回忆要求 k/v 上下文化** (RWKV token-shift / attention 混合 / 多层)。
玩具单层去上下文后, 该任务对任何读出机制都不可学——不是 state vs attention 之别。
→ 真实 v31 架构 (bridge/station 混合) 的 k/v 已上下文化, 此定律不阻碍 v36, 但玩具测试台必须带 token-shift。

### 6. 初始选择性墙 ⚠️
对齐后线性读出的 SNR ≈ √(DH / 块内写入数)。16 维 state 扛 112 个填充写入 → SNR 0.38 < 1,
噪声读出比无读出更糟 (模型学会压扁读出路径)。
→ **稀疏/门控写入** (内容掩码或可学习写入门) 是线性 state 家族的必要组件, RWKV-6/Mamba 的选择性是同一件事。

## 三、B (多state) 卡死的根因链 (已闭合)

排除项: 门(NLL=0仍卡) · aux毒 · 梯度不通(初始108×) · 容量(信息≥单state) · 表示能力(轮9证明可学)
根因链: **双路径无归一化 → 尺度竞争, head 无法 bootstrap (轮8) → LayerNorm 修复后 bank 可学 (轮9)
→ 但混合系数自由可学时会停在 0 (轮10), 需固定混入或 warmup 调度**

**v36 双路径读出的正确配方** (轮9-10 实证):
1. local 与 bank 各自 LayerNorm 后相加 (必需)
2. bank 混入系数**固定 1.0 或 warmup 调度**, 不要做成可学习参数从零自启
3. acc 突破剩余部分 = 预算/解码端问题 (bank 信号已在, margin 1.815 远超解码所需)

## 四、对 v36 正式实现的指令

1. 基础机制用已验证件: chunk 独立扫描 (s0=None) → bank → 门控读出 + 本chunk局部读出
2. 必须: token-shift 或等价上下文化(真实v31已有) · 稀疏/门控写入 · 检索头端到端 + aux暖启动
3. **双路径各自 LayerNorm + bank 固定混入(或 warmup 调度), 混合系数不可做成可学习参数从零自启** (轮9-10 实证)
4. rate/eta 数据依赖化 (RWKV-6/Mamba 方向) 是下一个杠杆 (eta 擦除增益 6×10⁶ 的来源)
5. 玩具 acc 绝对值不代表真实架构上限 (真实 k/v 上下文化 + 多层 + 大 DH); 结构性结论才可迁移

## 五、真架构实装 (v36_multistate.py v2 + v36_longctx.py, 2026-10-28)

设计: 全长连续 v31 前向 (零基座损失, ramp=0 严格≡v31) + chunk 边界前缀状态 bank
(经扩展的 `delta_scan_states(boundary_idx=)` 收割, detach) + 每站门控检索读出
(未来/本块掩码, down proj 0.002 小初始化, 无归一化, 0→1 ramp 暖启动)。
从 deqlmv31r_pt_full.pth 热启动, +1.03M 参数。

### 实装过程踩坑 (全部修复, 记录防再踩)
1. 独立分块编码 (v1): 预训练连续模型砍块 → 基座塌缩 (loss +0.55) → v2 改全长前向+边界bank
2. `net(ids)` 返回 logits 不是隐状态 → 显式站点链
3. **`capture_states` 内部 `self.eval()` 不恢复** → 训练时主干全程 no_grad, 梯度断供
   (探针: 权重未变/前向健康/net.training=False 三证据定位)
4. 长跑数据自建时 `y = x.clone()` → 模型学复制输入 (train loss 0.16) → 改真·下一token目标
5. MARMSNorm 把小信号归一化成单位噪声 → 读出路径去归一化, 靠 0.002 down 初始化保持起始≈0
6. `torch.compile@L=4096` 数值异常 (loss 12, 与 compile 无关的二次确认后排除; 真凶是 #3)

### 4096 长上下文结果 (500 步 finetune, 后缀 [2049,4096) NLL)

| 方法 | NLL |
|---|---|
| 零state (无历史) | 2.3477 |
| relay-s0 (2048 步单 state 接续) | 2.3377 |
| **v36-MS (32 块 bank 检索)** | **2.3228** |

v36-MS 全面领先且 500 步处仍未平台化 (~0.0005/25步 改善速率)。
**多 state bank 在价值窗口 (1k-4k+) 内首次于真实架构+真实数据上兑现超越单 state 接续。**

### 2000 步延长跑 (v2 配置, DELTA_STAGES=1, 每500步存档)

单调改善无回弹: 2.3228(475) → 2.3159(1000) → 2.3152(1500) → **2.3128(1800)** → 2.3136(1900)。
对 relay 优势扩大到 **−0.025 NLL** 并趋于渐近; 训练全程健康 (loss 2.0-2.7)。
延长跑增益开始减速 (~0.0002/100步) → 下一个杠杆: 每站中途注入 / 数据依赖 rate·eta / 更长距离。

### v3 实装结果 (每站中途注入 + 写入门 bias3, 2000 步) — 待课程式修复

- 初始即优于 relay: 2.2895 < 2.2959 < 2.3103 (零) ✓ 结构优势延续
- 但 2000 步训练后劣化至 2.3863 (+0.097 vs 自身初始; 训练中 spike 至 4.16)
- 对照 v2 同预算: 2.3128 (改善) → **v2 (单点末端注入) 仍是冠军**
- 根因指向: 5 注入点 + 门参数 + 5 读头在同一预算下协同不起来 (与玩具轮 5-8 同构)
  → 修复配方: 课程式 (冻结主干先训读头) + lr 减半 + ramp 暖启动延长, 未跑
- 写入门本身中性偏正 (基线 relay 因 0.95 门控从 2.3377 → 2.2959, 疑似轻微稳定化)
- 16384 终评再次 "CUDA device not ready" (三连, 均在重训练后的 capture 处)
  → 根治方向: 终评子进程化 / capture 分段 / TDR 调参; 本轮因崩溃未取得 16k 数字

**当前冠军: v2 配置 (单点末端注入, 无门) — v36ms_long.pth @1500步, 4096后缀 2.3152**

### 16k/64k 评估与长度外推定律 (subprocess 终评跑通, 零崩溃)

- 子进程隔离 + 读出 K 循环 + 分段 capture: **16k/64k 评估全程零崩溃** (三连崩根治 ✓)
- 但冠军 checkpoint @16384: 三方全崩到 ~10.1 (均匀分布), 零 == relay 完全一致
- 位置探针定位: **预训练 v31 尾窗零state @16384 = 2.2347 (健康)** → 数据/内核/位置全部无辜
- 根因: **256-finetune (K=2) 2000 步使 rate/eta 漂移 → 长度外推炸弹**
  (慢通道 λ≈0.9995, state 幅度 ∝T: 16k 时为 256 训练域的 ~64×, 漂移后爆炸)
- v4 (课程式+选择性+门) @16384: **v36 2.4354 < relay链 2.4432 < 零 2.4557** —
  长度漂移基线上 bank 仍胜 relay ✓

**定律: finetune 长度必须 ≥ 声明的推理长度, 或用数据依赖 rate/eta 约束漂移。**
→ E4 (16k 训练, chunk=128, K=128) 从"可选"升级为"必做": 训在 16k 才能兑现在 16k。

### 崩溃问题结案
- "CUDA device not ready" 三连崩: 根治确认 = **终评子进程化 + 读出 K 循环 + 分段 capture**
  (16k/64k 全程零崩溃); 4096 训练内探针保留单次 capture (健康)
- 历史教训: 大 K einsum 物化 >2GB 中间张量 → Windows TDR; 单内核 >2048 步循环 → TDR 风险
