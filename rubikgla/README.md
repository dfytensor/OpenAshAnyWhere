# Rubik-GLA 阶段一验证报告：核心公式被证伪，加一行衰减后复活

日期: 2026-09-17 | 环境: RTX 4090D / torch 2.14 / 小规模档 (4 层 × d128 × H4 × dh16)
代码: `models.py` / `tasks.py` / `run_phase1.py`（断点续跑, 结果逐项落盘）

## 一、实验设计

**被检验主张（SPEC 文档核心公式）**：

```
S_t = exp(skew(W_g x_t)) · S_{t-1} + k_t^T v_t        (非交换旋转门控, G ∈ SO(dh))
o_t = q_t · S_t
```

- 4 任务 × 4 模型 × 2000 步，同种子同预算：bracket / copy / reverse / fsm
- 对照：GLA（逐元素可交换门控，即被"升级"的对象）/ GRU / Transformer
- 工程修复：递归层无 pre-norm 会逐层复利爆炸（GLA 4 层即 inf），加 ln_in（RWKV/GLA 实现标配）

## 二、纯形式结果：H1 全面证伪

| task | rubik-纯 | gla | gru | tf |
|---|---|---|---|---|
| bracket | **0.508** | 1.000 | 1.000 | 1.000 |
| copy | **0.183** | 1.000 | 1.000 | 1.000 |
| reverse | **0.179** | 1.000 | 1.000 | 1.000 |
| fsm | **0.381** | 0.882 | 1.000 | 0.880 |

四任务全部随机水平（0.18 ≈ 六选一运气）。连最该受益非交换的 reverse 也是 0.179。
GLA 用 8.7 倍少的参数三任务满分。

## 三、机理诊断与一行抢救

**诊断**：G≈I 小初始化 + 纯旋转无衰减 ⇒ 状态退化为"全体写入的和"——
读出没有 recency 核（GLA 的 g<1 衰减天然形成指数位置加权，这才是它作为
记忆的工作原理）。旋转保范不遗忘，丢掉了检索结构。

**抢救（一行）**：`S_t = λ ⊙ (G_t S_{t-1}) + kv`，λ 为逐头逐通道 sigmoid 标量
（初始 0.27）。λ 与矩阵乘可交换，**非交换性完整保留**，recency 核恢复。

## 四、抢救结果：复活，且 fsm 四模型第一

| task | rubik-decay | rubik-纯 | gla | gru | tf |
|---|---|---|---|---|---|
| bracket | 1.000 | 0.508 | 1.000 | 1.000 | 1.000 |
| copy | 1.000 | 0.183 | 1.000 | 1.000 | 1.000 |
| reverse | 1.000 | 0.179 | 1.000 | 1.000 | 1.000 |
| **fsm** | **0.970** | 0.381 | 0.882 | 1.000 | 0.880 |

- 三任务从随机拉满——"无衰减是失败主因"确诊（先诊断后修复，两步闭环）
- **fsm（状态跟踪）上 0.970 为四模型第一**，超 GLA 0.882 / TF 0.880——
  这是唯一支持 H1 方向的正面证据，且恰好落在架构的目标任务类上

## 五、判决与边界

1. **文档核心公式（纯形式）被证伪**：无衰减的旋转门控不可学习（在本预算内）。
   文档 SPEC §2 的公式需要修订为带 λ 衰减的版本。
2. **修正后机制成立且在状态跟踪上显示优势**——但 copy/reverse/bracket 上
   只是追平基线，未超越（H1 的"更高"仅 fsm 部分支持）。
3. **诚实边界**：单种子、2000 步、L≤97、无低秩/SWA 混合/长度外推测试；
   fsm 上 GRU 仍满分。参数量不对等（rubik 2.32M vs gla 0.27M）。
4. 速度：纯串行 + matrix_exp ≈ 0.3-2.3s/step（视 GPU 争用），验证了
   SPEC 风险表"串行递归慢"条目——分块并行/前缀扫描是下一阶段的工程前提。

### 结论

1. **fsm 优势跨种子复现**: rubik 均值 0.985 vs gla 0.916 (+0.07 稳定), 仅次于 GRU 满分
2. **长度外推 4x**: rubik fsm 仅 -0.7pp (0.988->0.981); reverse 与 gla 同为满分;
   **TF 崩 38pp (0.96->0.59)** — 位置编码外推失败 vs 递归记忆平外推的对照
3. GRU 在玩具任务饱和; rubik 对 GRU 的差异化需 enwik8/LRA 级任务
4. 工程: B=128 + eval256 峰值显存 11.9GB (此前 B=32 仅 1-2GB), 单位算力成本降 4 倍
5. 事故记录: 双 Start-Process 并发写同一 JSON + 共享 GPU 导致 CUDA illegal address,
   旧进程最终写入清场 — 教训: 后台任务启动前必须确认旧进程清零
