# OpenASH 选择性记忆机制研究 — 完整过程报告

> 从"cummax 无法选择性记忆"到"真实模型 12K 上下文无标记针检索 87.5%"
> 全程 9 个里程碑、30+ 轮实验，每步量化验证。
> 约束：**不使用任何既有方案**（慢尺度记忆 / 内容门控 / F-layer 线性递推 / 双路状态），
> 在 OpenASH v1（cummax + gen_model）骨架内从头设计新机制。

---

## 1. 起点：OpenASH v1 为何失败

### 1.1 任务定义

**CopyFirst**：`[目标token] + [N个噪声] + [END]`，最后一位输出位置 0 的 token。
**CopyAnywhere**：目标在任意位置，按查询输出。

**OpenASH v1**：多头 cummax（累积最大值，单调递增）+ gen_model（5 分支乘性交互），
SFT loss=3.60（同规模最优 LM 先验）。

### 1.2 失败根因

cummax 状态单调递增、只保留"运行最大值"：
- **次序信息被摧毁** —— 无法区分"第一个"和"任意一个"
- token 专属信息被后续噪声的最大值覆盖
- CopyFirst best_loss=1.6（≈35% 水平），**选择性记忆失败**

## 2. 攻克路线（谁攻克了谁）

### 阶段 A：玩具级 CopyFirst（openash_age.py → openash_age2.py）

| # | 谁（机制） | 攻克谁（问题） | 结果 |
|:--|:--|:--|:--|
| A1 | 软门 cummax + 乘性读出 | — | 86.7%@4，64 崩（软更新侵蚀首值） |
| A2 | 硬门 β=40 | 侵蚀 | 梯度饱和，学不动（3.30） |
| A3 | **STE 硬门**（前向硬 max + 反向软梯度） | 侵蚀 + 可学习两难 | 梯度通了，读出仍弱 |
| A4 | **结构化读出**（age 门控 σ(γ(A−θ)) + 关联查找） | 弱读出 | 0.63 loss，96.1%@4 |
| A5 | 全局迟滞 margin | 长距生存 | 首写也被挡（1.26） |
| A6 | 随龄抗写（margin 随龄增长） | 生存 | 64: 43%，65K: 12.5%，但短距回退 |
| A7 | **首写倍增**（t=0 键 ×(1+amp) 写入） | **长距生存** | **✅ 100% @ 4→65,536 全距** |

**核心机制**：Max-Age 追踪器 = cummax 主状态 + age 寄存器（通道"当前最大值存活时长"）
+ 首写放大。第一个 token 的幸存通道 = 全局最大 age → 可识别。
**洞察**：给"被查询的写"结构性优先权，单调性从诅咒变保险箱。

### 阶段 B：CopyAnywhere（openash_age_any.py → openash_queryfirst.py）

| # | 谁（机制） | 攻克谁（问题） | 结果 |
|:--|:--|:--|:--|
| B1 | gap 查询 + 高斯选龄 | — | near 28%（邻居泄漏） |
| B2 | σ=0.5 / σ 退火 | 泄漏 | 梯度死/仍失败 |
| B3 | 探针定位：**单轨容量墙** | — | 写入需胜过旧最大值：margin 大写不进（70 步冻结），小则被盖 —— 不可两全 |
| B4 | **QueryFirst**（查询前置 + 查询门控放大写 + 幅度读出） | **容量墙** | **✅ 100% @ 4→65,536 任意位置** |

**核心机制**：序列开头给查询位置 P，t==P 时键 ×(1+amp) 放大写，END 时幅度门控读出。
**洞察**：把"该记什么"从隐式变成显式——查询在前，写才有目标。

### 阶段 C：真模型集成 M1（openash_reg.py）

| 谁（机制） | 攻克谁（问题） | 结果 |
|:--|:--|:--|
| FactRegister（768×12 真 OpenASH + 标记事实放大写 + 幅度门控注入） | 玩具→真实语言鸿沟 | **250 步收敛，loss 归零，100% @ ≤1024** |

训练：真实中文语料 20 万条，随机位置插入 `[MARK_OPEN] 张三最喜欢的数字是七 [MARK_CLOSE]`，
尾部提问，答案位损失 ×5。86.1M 参数，bf16。

### 阶段 D：基座长序列稳定性（openash_stable.py）

| 谁（机制） | 攻克谁（问题） | 结果 |
|:--|:--|:--|
| **逐位置状态范数 cap**（每层每位置 cummax 状态超半径 R 按比例缩放，可微/保序/训练推理一致） | cummax 状态长序列漂移（基座 loss 2048 爆 3.98、4096 爆 6.23） | 回忆 2048/4096: 68.8%/56.2% → **93.8%/87.5%** |

### 阶段 E：多事实内容寻址 M2（openash_reg2.py）

| 谁（机制） | 攻克谁（问题） | 结果 |
|:--|:--|:--|
| **多槽寄存器（8 槽）+ cos 内容寻址读出**（问题键匹配槽查询键选槽） | 单事实 → 多事实区分 | 2 事实 **81.2%@512**（随机基线 4%），3 事实 68.8% |

### 阶段 F：无标记针 M3（openash_reg3.py）

| # | 谁（机制） | 攻克谁（问题） | 结果 |
|:--|:--|:--|:--|
| F1 | **学习式写入门**（g_t=σ(Wg·x_t)，STE 端到端；门开累积 span，门落提交槽） | 无标记 → 该存什么 | 250 步 100%@≤1024 |
| F2 | 消融+探针：**轮转槽覆盖**是 4096 崩溃真因（~30 填充提交轮一圈盖掉针）；K 匹配为负说明 512-2048 靠基座撑场 | 定位病根 | 4096 37.5% |
| F3 | **写一次永不覆盖**（只进空槽，满则丢弃）+ **门稀疏正则** | 槽覆盖 | 4096: 37.5% → **87.5%**；2048 → 93.8% |
| F4 | n=16 大样本验证（8K"瓶颈"为 n=8 采样方差假象） | 测量可靠性 | **8192: 93.8%，12288: 87.5%** |

## 4. 机制清单（全部新设计，零旧招）

1. **Max-Age 追踪器**：cummax + 通道 age 寄存器（存活时长）+ 高龄门控读出
2. **首写倍增**：t=0 键 ×(1+amp) —— 结构性不可覆盖
3. **QueryFirst**：查询前置 + 查询门控放大写 + 幅度读出
4. **STE 硬门**：前向硬 max（永不侵蚀）+ 反向软梯度（可学习）
5. **逐位置范数 cap**：基座长序列稳定（可微/保序）
6. **多槽 + cos 内容寻址**：问题键匹配槽查询键
7. **学习式写入门**：门决定"该存什么"（端到端学习）
8. **写一次永不覆盖**：空槽才写，满则丢弃 —— 被查询内容必然存活

**统一哲学**：单调寄存器（cummax 家族）的记忆 = "被查询的写获得结构性优先权"。

## 6. 遗留问题

- 12288+ 的零星错误（6-12%）—— 基座长上下文边缘效应，需更彻底的层级稳定化
- 多事实（M2 3-4 事实）准确率 ~60-70% —— 槽分配策略（内容相似复用）可提升
- 真 NIAH 语义问题（问题与事实措辞不同）—— 需要更强的查询-内容语义匹配

## 7. 大规模重训流程（最终设计 → 规模化）

### 目标架构（0.5B-2B 级）

```
OpenASHStable-大 (1024-1536 hidden, 24-36 层)
  ├ 逐位置范数 cap (每层可学习 R)
  ├ MultiFactRegister (16-32 槽): 学习式写入门 + 永不覆盖 + 放大写 + softmax竞争读出
  └ 长上下文: 2048-4096 序列预训练
```

### 阶段化流程

| 阶段 | 内容 | 验证门槛 |
|:--|:--|:--|
| 0. 数据 | 全量 pretrain (1.2GB+) 按 2048/4096 打包；合成事实（多事实+模板变体）插入；混合 sft_t2t_mini | — |
| 1. 骨干预训练 | 256→512→1024→2048 课程长度，0.5B 起步，4090 多卡 DDP，bf16 | PPL 随长度平缓（cap 生效）|
| 2. 机制无监督融入 | 预训练数据内嵌事实+提问（答案在尾部，损失只算答案位） | 检索信号出现 |
| 3. 任务微调 | 监督门 BCE(负加权) + 答案位×5 + 门稀疏；序列 1024-2048；lr 1e-4 | NIAH 矩阵 |
| 4. 评估矩阵 | 单针/多针/语义变体/8K-32K 距离；消融（寄存器/cap/监督门开-关） | 每阶段 checkpoint 留存 |

### 工程要点
- bf16 + autocast（已验证）；DDP（train_full_sft.py 有骨架）；长序列激活检查点 + 梯度累积
- 计算估算：0.5B / 4096 序列 / 20 亿 token ≈ 4×4090 数天级

### 诚实风险
1. cummax 缩放行为未知（768 级已验证，1B 级是最大问号；FRSM 谱系只到 60M）
2. 长序列预训练是已知硬骨头（PPL 随长度 +47%~1127% 教训）——cap 缓解但需课程验证
3. 建议先 0.5B 级完整走四阶段，验证收益后再决定 2B 级

## 8. 定位：是通用 LLM 吗？

**不是**。本管线产出的是"**记忆增强（NIAH 级检索）的中文基座模型**"。

| 维度 | 本管线 | 通用 LLM |
|:--|:--|:--|
| 预训练数据 | ~3 亿 token 单一语料 | 1T+ token 多语料 |
| 对齐 | SFT 混合（无 DPO/RLHF） | SFT → DPO → RLHF |
| 能力验证 | NIAH 事实检索 | CEval/MMLU/GSM8K/代码/对话 |
| 上下文 | 2K-4K 训练，12K 检索 | 32K-128K+ |

**补全为通用 LLM 的四步**：
1. 预训练数据扩到 100B+ token（最大数量级鸿沟）
2. 对齐：SFT → DPO → RLHF（train_dpo.py / train_grpo.py 骨架已存在）
3. 多任务评估：CEval/MMLU/GSM8K/代码
4. 长上下文（32K+）与部署优化

**真优势**：O(1) 推理状态 + 线性时间——有限硬件上跑长上下文的记忆增强 LLM，
是 Transformer（128K 上下文需巨额 KV cache）不具备的效率卖点。
